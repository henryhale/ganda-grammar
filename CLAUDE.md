# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

ganda-grammar corrects Luganda spelling and grammar with deterministic rules. Each rule cites the published
orthography or grammar it comes from. It's pure Python with no runtime dependencies, and it uses no model.

## Commands

```
pip install '.[test]'             # required before tests, and again after changing src/ (no editable install, see Layout)
pytest                             # all tests
pytest tests/test_rules.py -k SPLIT_LOC          # one rule's example tests
pytest "tests/test_rules.py::test_rule_example[SPLIT_LOC:mukibuga]"
ganda-grammar correct --json "na abantu"         # see the edits the rules make
pip install '.[mine]'             # adds `datasets` for `fix --hf` / `mine --hf`
```

The system has `python3` but no `python` on PATH.

## Layout

The package is `src/` itself, not `src/ganda_grammar/`. Hatchling maps `src` → `ganda_grammar` in the wheel, and
code imports `ganda_grammar.*`, so tests only run against an installed copy. Hatchling can't make an editable install
with that mapping, so reinstall after every change to `src/`.

The version comes from the git tag through hatch-vcs: tag `v0.1.0` builds `0.1.0`, and untagged commits build a
`.devN` version. Never set it in `pyproject.toml`.

## Architecture

- `src/rules/__init__.py` holds the engine. `correct(text)` splits text into sentences (`base.sentences`) and gets the
  sentence's tokens from `base.luganda_tokens`. That function returns `[]` when the sentence doesn't read as Luganda
  (judged by word shape, the `ENGLISH` and `FOREIGN` word lists, and a 60% threshold), so no rule touches it. The
  engine then collects edits from each family in `FAMILIES = (agreement, elision, joining, orthography)`. **Order is
  priority:** when two edits overlap, the earlier family's edit wins. Overlaps are only checked within a sentence.
- Each family module (`agreement.py`, `elision.py`, `joining.py`, `orthography.py`) exports:
  - `RULES`: `{rule_id: (description, source citation)}`
  - `edits(text, toks) -> [Edit]`

  `Edit` offsets point into the **original** text, so callers can underline each edit or undo it.
- **Rule descriptions are tests.** Each description is `"what it corrects: before → after, before → after"`.
  `tests/test_rules.py` parses every `before → after` pair after the colon and asserts that `correct(before)` gives
  `after` with exactly that one rule firing. Every rule must have at least one example and a non-empty source. When
  you add or change a rule, its description has to stay in this format, and each example must trigger only that
  rule.
- Rule data:
  - `src/rules/spellings.tsv` drives `ORTH_LENGTH`. It's generated by `scripts/build_spellings.py` from the FSI
    glossary PDF text and corpus counts, so don't hand-edit it without that context.
  - `src/rules/verbs.txt` is used by `joining.py`.
  - `agreement.NOUNS` (about 230 nouns of known class) is also imported by `scripts/build_spellings.py`.
  - Data files ship as package data (`*.tsv`, `*.txt` in `ganda_grammar.rules`).
- `src/fix.py` (`ganda-grammar fix`) writes corrected copies of `.txt`/`.jsonl` files or a Hugging Face dataset into
  a new folder:
  - Lines and rows that don't change are copied byte for byte, and the input is never overwritten.
  - The work is split into chunks across a `ProcessPoolExecutor`.
  - `--log` writes one JSONL row per changed line or field, with edits that replay against `original`.
- `src/mine.py` (`ganda-grammar mine`) writes only the changed sentences, as before/after pairs.
- `src/cli.py` imports each subcommand's module lazily.

## Notebooks and scripts

- `notebooks/build_wordlist.ipynb` counts Luganda word forms across Hugging Face datasets and writes
  `luganda_words/luganda_words.tsv`. It's meant for Kaggle, and it uses `ganda_grammar.rules.base`
  (`sentences`, `luganda_tokens`, `looks_luganda`) to decide which text is Luganda. Its output is gitignored.
- `scripts/bundle_notebook.py` writes the `*_selfcontained.ipynb` copy of a notebook. The copy starts with
  `%%writefile` cells holding all of `src/` (as `ganda_grammar/`) and `scripts/`, so the notebook runs without the
  repo. Rerun it after changing the package if the self-contained notebook must stay current. Edit
  `build_wordlist.ipynb`, never the self-contained copy.
- Notebooks are not part of the package, and the package is Apache-2.0 only.

## Docs

- `docs/` is an MkDocs Material site. `.github/workflows/docs.yml` builds it with `mkdocs build --strict` and deploys
  it to GitHub Pages from `main`.
- `docs/hooks.py` replaces `<!-- RULES -->` in `docs/rules.md` with a table built from the installed
  `ganda_grammar.RULES`. Reinstall the package before `mkdocs serve`, or the table shows the old rules.
- The README is a short landing page and doubles as the PyPI description, so its links must be absolute URLs.
  Details belong in `docs/`.

## Conventions

- Every rule needs a citation (Walusimbi 2015, *Empandiika y'Oluganda Entongole*, or Sternefeld & Sseguya 2015).
  Code comments cite the section (for example `§1.3(r)`) that justifies each exception.
- Rules favour precision. Ambiguous cases are left alone on purpose, and `test_left_alone` in `tests/test_rules.py`
  records them. Some examples: `wa` ("where?") is never elided, possessive `bwe` is never elided, and after an
  apostrophe the adjective isn't checked for agreement. Add a left-alone test when you add an exception.
